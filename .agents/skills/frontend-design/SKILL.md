# Frontend Design

Use this skill when building new UI or making an existing interface look more intentional.

## Workflow

1. Identify the product, audience, and the screen's one main job.
2. Choose one clear visual direction before coding: palette, typography, layout rhythm, and one signature detail.
3. Avoid default AI UI: purple gradients, generic card grids, same-looking SaaS dashboards, decoration without information.
4. Reuse this repository's existing components, CSS variables, spacing, and manager/customer visual systems before inventing new ones.
5. Build responsive states, keyboard focus, empty/loading/error states, and reduced-motion behavior as part of the UI, not as afterthoughts.
6. Take a screenshot when the environment supports it and the change is visual.

## Quality bar

- Every visual choice must explain or clarify the content.
- Typography should establish hierarchy; do not rely only on size and bold weight.
- Color should encode status or brand mood; never use color alone for meaning.
- Motion should guide attention; remove it if it only adds noise.
- Copy should use plain verbs and user-facing language.

## Output

When reporting back, mention the visual direction, the files changed, and the validation run. Keep prose short unless the user asks for a design rationale.
